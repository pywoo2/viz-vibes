OVERVIEW
--------
Built viz-vibes.com from scratch — a personal music player with interactive
WebGL visualizers, floating media overlays, a shared Tamagotchi pet, and a
guestbook. Started from a simple GitHub Pages site (pywoo2.github.io) with
static HTML, ended with a full Next.js + FastAPI stack deployed on Railway
with Cloudflare R2 storage and a custom domain.

================================================================================
PHASE 1: INITIAL MUSIC PLAYER (Single HTML File)
================================================================================

Started with a bare index.html on pywoo2.github.io. Built a Spotify-style
music player in a single HTML file:

- Gruvbox dark theme with CSS variables
- Sidebar with track list (left), main area (right), bottom player bar
- Full playback controls: play/pause, next/prev, shuffle, repeat (off/all/one)
- Progress bar with click-to-seek
- Volume slider
- Keyboard shortcuts (Space, arrows)
- Equalizer bars animation on the active track
- Track list with staggered fade-in animations

The player fetched tracks from a static tracks.json file. Audio files were
.wav files stored locally.

PHASE 2: THEME SYSTEM
================================================================================

Added 6 color themes, all using CSS custom properties:
- Gruvbox (warm retro green)
- Nord (cool arctic cyan)
- Rosé Pine (soft purple/pink)
- Tokyo Night (deep blue/purple)
- Catppuccin (pastel lavender)
- Midnight (ultra-dark ice blue)

Each theme defined ~30+ CSS variables (--bg, --fg, --accent, --glass-bg, etc).
Theme picker dropdown in the sidebar header. Selection saved to localStorage.

Later simplified to a single monochrome theme (black/white/gray) to match
the liquid glass aesthetic. Eventually added 4 color modes for the visualizer:
mono, rainbow, inverted, deep red.

PHASE 3: LIQUID GLASS EFFECTS
================================================================================

Researched iOS 26 liquid glass design. Implemented:

- backdrop-filter: blur(40px) saturate(180%) on sidebar and player bar
- Semi-transparent backgrounds (rgba with 0.7-0.9 opacity)
- Subtle white border lines (rgba(255,255,255,0.08))
- Inset box-shadows for edge glow
- Animated specular highlight on sidebar (radial gradient that shifts)
- Mouse-tracking highlights (JS updates CSS via refs, not state, for perf)
- Track hover glass ripple effect
- Play button spring press animation (cubic-bezier overshoot)
- Heart pulse animation on like click
- Active track breathing glow (4s box-shadow cycle)
- Sidebar edge glow on hover (vertical light line)
- Grain texture overlay (SVG feTurbulence at 3% opacity) — later removed

Key technical challenge: Tailwind v4's @import strips backdrop-filter when
using CSS variables. Fixed by hardcoding blur values instead of var(--glass-blur).

PHASE 4: INFRASTRUCTURE — RAILWAY + CLOUDFLARE R2
================================================================================

Moved off GitHub Pages to a proper backend setup:

BACKEND (FastAPI on Railway):
- server.py → main.py with FastAPI
- Auto-discovers songs from R2 bucket (no more tracks.json)
- GET /api/tracks — lists audio files with R2 URLs
- POST /api/tracks/{title}/like — increment likes (stored in R2 _likes.json)
- POST /api/tracks/{title}/unlike — decrement likes
- GET /api/health — health check
- CORS middleware allowing all origins
- R2 credentials via environment variables (R2_ACCESS_KEY, R2_SECRET_KEY)

STORAGE (Cloudflare R2):
- Bucket: peters-music
- Audio files (.wav) stored at root
- Art/media files under art/ prefix
- Likes stored as _likes.json
- Notes stored as _notes.json
- Pet state stored as _pet.json
- Public access via r2.dev URL
- CORS configured for cross-origin audio

HOSTING (Railway):
- Two services: frontend (peters-music) and backend
- Frontend: Next.js Docker build with standalone output
- Backend: Python 3.12 slim with uvicorn
- NEXT_PUBLIC_API_URL passed as Docker build arg
- Custom domain: viz-vibes.com via Cloudflare DNS

DOMAIN (Cloudflare):
- viz-vibes.com purchased via Cloudflare Registrar
- CNAME to Railway
- DNS only (no proxy) for Railway SSL
- R2 public dev URL for media streaming

PHASE 6: WEBGL VISUALIZERS
================================================================================

Built 6 audio-reactive visualizer modes, all as GLSL fragment shaders:

1. NOISE FIELD (default) — 3-octave 2D simplex noise
   - Bass drives large slow movements
   - Mids create medium flowing patterns
   - Highs add fine detail
   - Center radial glow scales with energy
   - Mouse warps coordinate space (gravity well)

2. WAVEFORM — audio-reactive sine wave line
   - 3 layered sine waves at different frequencies
   - Bass/mid/high control amplitudes
   - Mouse pulls the wave toward cursor (gaussian falloff)
   - Glow effect around the line

3. PARTICLES — floating dots
   - 8-25 particles (count scales with energy)
   - Each has unique orbital path (golden angle distribution)
   - Bass makes them expand outward
   - Speed scales subtly with energy
   - Mouse attracts nearby particles

4. GRID — perspective tunnel
   - Polar coordinate grid in tunnel view
   - Tunnel center shifts with bass/mids + mouse
   - Segment count changes with highs
   - Line thickness pulses with bass
   - Scan line effect driven by energy

5. PLASMA — layered flowing sine field
   - 5 overlapping sine wave layers
   - Each modulated by different frequency band
   - Sharp contour lines that pulse with energy
   - Center energy burst
   - Mouse warps coordinates before calculation

6. NONE — black screen with subtle mouse glow + click effects

CLICK EFFECTS (4 types, togglable):
- Ripple: expanding thin ring from click point
- Burst: radial rays + center flash
- Shockwave: thick expanding bright disc
- None: disabled

TECHNICAL DETAILS:
- Raw WebGL (no Three.js for the 2D version)
- Full-screen quad (two triangles)
- Shader recompiles on mode switch
- Uniforms: time, bass, mid, high, energy, resolution, mouse, click, clickType, colorMode
- Mouse tracking via window mousemove (refs, not state)
- Touch support: touchmove for gravity, touchend for click effects
- Canvas fills viewport via position:fixed on #visualizer-bg
- ResizeObserver for responsive canvas sizing
- DPR capped at 1.5 on mobile (was 2) for performance

COLOR MODES:
- Mono: vec3(brightness) — white on black
- Rainbow: rainbow(hue) function using cosine color cycling
- Inverted: vec3(1.0 - brightness) — black on white
- Deep Red: (brightness * 0.7, brightness * 0.05, brightness * 0.05)

3D SPHERE EXPERIMENT (reverted):
- Briefly wrapped shaders onto a Three.js sphere with OrbitControls
- Camera inside looking out (planetarium dome)
- Reverted because: UV seam artifacts, disorienting rotation, shaders
  designed for 2D not 3D, mouse interaction broke

PHASE 7: FLOATING MEDIA OVERLAY (FiguresLayer)
================================================================================

Shows photos and videos as faint overlays behind the visualizer:

EVOLUTION:
1. Started with procedural stick figure drawings (terrible)
2. Switched to architectural line drawings (also terrible)
3. Switched to real public domain images from Wikimedia Commons
   (Da Vinci, Fibonacci, Doré, Tesla patents, CS diagrams)
4. Final: user's personal photos + videos from R2

CURRENT IMPLEMENTATION:
- Fetches media list from GET /api/media (dynamic from R2)
- Shows 3 items at a time (2 on mobile)
- At least 1 is always a video
- Cycles every 15s (25s on mobile) — one fades out, new one fades in
- Staggered fade-in on initial load (800ms apart)
- New items placed with minimum distance check (25% viewport)

INTERACTIONS:
- Left-click + drag: rotate in 3D (CSS perspective + rotateX/Y)
- Right-click + drag: move position (percentage-based)
- Scroll wheel: zoom in/out (0.3x to 3x scale)
- Context menu disabled site-wide

STYLING:
- opacity: 0.12 (mono mode) or 0.2 (rainbow mode)
- filter: grayscale(100%) brightness(3) contrast(0.6) — mono
- filter: brightness(1.5) contrast(0.8) saturate(1.2) — rainbow
- mixBlendMode: screen
- Videos: autoPlay, loop, muted, playsInline

BACKEND:
- GET /api/media scans R2 art/ prefix
- Returns { src, type } for each image/video
- Supports: jpg, jpeg, png, gif, webp, svg, mov, mp4, webm, m4v
- Dynamic — just drop files in R2 and they appear

PHASE 13: TAMAGOTCHI PET
================================================================================

Shared virtual pet that all users care for together.

BACKEND:
- Pet state in _pet.json on R2
- Stats: hunger (0-100+), happiness (0-100+), cleanliness (0-100+)
- Time-based decay: every hour, hunger +5, happiness -3, cleanliness -2
- Actions: feed (-5 hunger), play (+5 happiness, +2 hunger), clean (+5 cleanliness)
- Stats can exceed 0-100 (overfeeding mechanic — bar turns red)
- Evolution stages: egg(150) → baby(600) → kid(3000) → teen(15000) → adult
- Mood calculation based on average stats
- Endpoints: GET /api/pet, POST feed/play/clean/rename
- Community todo log: GET/POST /api/pet/todos (max 20, stored in R2)

FRONTEND:
- Canvas-based pixel art rendering (16x16 grid, 2fps)
- 4-color monochrome palette (GameBoy green: #0f380f, #306230, #8bac0f)
- 12 hand-crafted sprite frames:
  - Egg: wobble animation (2 frames)
  - Baby: idle bounce, eating, sad, dirty, sleeping, playing
- Retro Tamagotchi device shell (dark gradient, rounded corners, shadow)
- Green LCD screen with inset shadow
- Stat bars (FED, JOY, CLN) — turn red when overfed (>100 or <0)
- Evolution progress bar (emoji → bar → next emoji, no numbers)
- Three round retro buttons (feed, play, clean)
- Click pet name to rename (inline edit)
- Floating emoji feedback on actions (🍔/🎾/✨ pop from button, drift up)
- Screen flash animation on button press

3-COLUMN LAYOUT:
- Left: Instructions card (how to care, evolution stages + progress)
- Center: Tamagotchi device
- Right: Community log (chat-style card, auto-scroll to bottom)

DEPLOYMENT WORKFLOW
================================================================================

Throughout the session, the deploy process was:

1. npm run build (in frontend/)
2. git add -A && git commit && git push
3. Copy frontend to /tmp, strip node_modules/.next
4. railway link + railway service link peters-music + railway up --detach
5. (For backend) Same but with backend service

Total commits: ~60+
Total deploys: ~40+
Total agents spawned: ~80+

The multi-agent workflow was key — research, implementation, and testing
agents running in parallel, communicating via a blackboard file
(.blackboard.md and .mobile-blackboard.md).
