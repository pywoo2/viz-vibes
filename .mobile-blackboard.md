# Mobile Responsive Blackboard

## Current State
- Desktop UI works well: sidebar (280px), visualizer (full viewport), bottom player bar, RHS picker
- Mobile shows "best experienced on desktop" message and hides everything
- No mobile layout exists yet
- Need to support: phones (< 768px) and tablets/iPads (768px - 1024px)

## Design Direction
- DO NOT break the desktop layout
- Replace the "best experienced on desktop" block with an actual mobile UI
- Mobile layout should be a simplified single-column view
- iPad should work with a narrower sidebar or collapsible sidebar

## Mobile Layout Plan
### Phone (< 768px):
- No sidebar — full screen visualizer
- Bottom player bar stays (compact version)
- Track list accessible via a slide-up drawer/modal
- RHS picker hidden or moved to a hamburger menu
- Note input moves into the drawer
- Song title + controls in a compact bottom bar

### iPad (768px - 1024px):
- Sidebar collapses to narrow mode by default (~200px)
- Everything else scales down
- RHS picker stays but smaller
- Bottom bar slightly smaller

## Research Findings

### 1. Breakpoints (consensus from BrowserStack, Bootstrap, MDN, CSS-Tricks)

Use THREE breakpoints, mobile-first:
```
/* Phone (default): 0 - 767px */
/* Tablet: 768px - 1023px */
/* Desktop: 1024px+ */

@media (min-width: 768px) { /* tablet styles */ }
@media (min-width: 1024px) { /* desktop styles - current layout */ }
```

Current code uses `max-width: 768px` to hide desktop and show mobile-block. We need to REPLACE that approach entirely.

### 2. Sidebar-to-Drawer Pattern (Vaul / shadcn/ui approach)

**On desktop (1024px+):** Keep sidebar as-is (grid column).
**On tablet (768-1023px):** Narrow sidebar (~200px), no resize handle.
**On phone (<768px):** Replace sidebar with a bottom-sheet drawer.

### 4. WebGL Visualizer on Mobile (YES, keep it, but optimize)

**Key findings from MDN, ARM WebGL docs, and optimization articles:**

**A. Reduce resolution on mobile:**
```ts
// In Visualizer component, detect mobile and reduce pixel ratio
const isMobile = window.innerWidth < 768;
const dpr = isMobile
  ? Math.min(window.devicePixelRatio, 1.5)  // cap at 1.5x on mobile
  : Math.min(window.devicePixelRatio, 2);    // cap at 2x on desktop

canvas.width = canvas.clientWidth * dpr;
canvas.height = canvas.clientHeight * dpr;
```
On iPhone (3x DPR), rendering at full res = 9x pixels. Capping at 1.5x = only 2.25x pixels -- massive perf win, barely visible quality loss on small screens.

**B. Throttle to 30fps on mobile:**
```ts
let lastFrame = 0;
const targetFPS = isMobile ? 30 : 60;
const frameInterval = 1000 / targetFPS;

function render(time: number) {
  requestAnimationFrame(render);
  const delta = time - lastFrame;
  if (delta < frameInterval) return;
  lastFrame = time - (delta % frameInterval);
  // actual render here
}
```

**C. Simplify shaders on mobile:**
- Reduce number of fragment shader operations
- Use simpler visualizer modes by default on mobile (e.g., waveform instead of heavy particle effects)
- Avoid expensive blur/glow post-processing on mobile

**D. Disable figures/notes layers on mobile by default:**
The 3D CSS transforms on floating images/notes are expensive on mobile. Disable by default, let user toggle on.

**E. Pause rendering when drawer is open:**
When the track drawer is expanded, pause the visualizer to save GPU cycles.

### 6. Full Mobile Layout Strategy (replacing mobile-block)

**Current state in page.tsx:**
```tsx
<div className="mobile-block">  {/* shows on <768px */}
  <p>viz-vibes</p>
  <p className="mobile-sub">best experienced on desktop</p>
</div>
<div className="desktop-only"> {/* hidden on <768px */}
  {/* everything */}
</div>
```

**New approach -- single layout that adapts:**

Instead of two separate DOM trees, use ONE layout and adapt with CSS + conditional rendering:

```tsx
// In page.tsx, detect mobile with a hook:
const [isMobile, setIsMobile] = useState(false);
useEffect(() => {
  const check = () => setIsMobile(window.innerWidth < 768);
  check();
  window.addEventListener('resize', check);
  return () => window.removeEventListener('resize', check);
}, []);
```

Then:
- Remove `mobile-block` div entirely
- Remove `desktop-only` class -- make the grid layout responsive
- On mobile: `grid-template-columns: 1fr` (single column, no sidebar)
- Render Sidebar content inside a Vaul Drawer on mobile
- Keep PlayerBar at bottom always
- Keep Visualizer as full-screen background always
- Hide VisualizerPicker (or put in hamburger menu)
- Hide note-input (or put in drawer)
- Hide FiguresLayer and NotesLayer on mobile by default

**CSS grid change:**
```css
/* Base (mobile-first) */
.app-layout {
  display: grid;
  grid-template-columns: 1fr;
  grid-template-rows: 1fr auto;
  height: 100vh;
  height: 100dvh; /* dynamic viewport height -- accounts for mobile browser chrome */
}

/* Tablet */
@media (min-width: 768px) {
  .app-layout {
    grid-template-columns: 200px 1fr;
  }
}

/* Desktop */
@media (min-width: 1024px) {
  .app-layout {
    grid-template-columns: var(--sidebar-width, 280px) 1fr;
  }
}
```

Use `100dvh` instead of `100vh` on mobile. `100vh` on iOS does NOT account for the browser address bar, causing content to be cut off. `100dvh` (dynamic viewport height) adjusts as the address bar shows/hides.

### 7. Touch Interaction Considerations

- Progress bar: needs larger touch target on mobile (already has padding: 10px 0, good)
- Track items: 48px min-height is good (Apple recommends 44px minimum)
- Remove hover effects on mobile (they cause "sticky hover" on touch):
```css
@media (hover: none) {
  #track-list li:hover { background: none; }
  .like-btn:hover svg { fill: rgba(255, 255, 255, 0.5); }
  #progress-container:hover { height: 3px; }
  #progress-container:hover #progress-bar::after { transform: translateY(-50%) scale(0); }
}
```
- Add touch event handling for progress bar (current mousedown/mousemove won't work on mobile -- need touchstart/touchmove/touchend)

### 8. Prioritized Implementation Order

1. **Phase 1:** Add viewport meta tag with `viewport-fit=cover`. Add `100dvh` support.
2. **Phase 2:** Replace mobile-block with actual mobile layout. Single-column grid on <768px. Keep visualizer background.
3. **Phase 3:** Compact player bar on mobile (hide volume, hide shuffle/repeat, smaller play button).
4. **Phase 4:** Install Vaul. Create MobileDrawer component wrapping Sidebar track list.
5. **Phase 5:** WebGL optimizations (cap DPR, throttle FPS, simpler default viz).
6. **Phase 6:** Tablet layout (narrow sidebar, smaller controls).
7. **Phase 7:** Touch event handling for progress bar. Remove hover states on touch devices.
8. **Phase 8:** Polish -- safe area insets, drawer snap points, animations.

## Mobile UI Inspiration

Research conducted 2026-03-28 across Spotify, Apple Music, TIDAL, YouTube Music, SoundCloud, and Dribbble/Behance design communities.

### What the Best Players Do (and What We Should Steal)

#### 1. The Two-Layer Player Pattern (STEAL THIS)

Every premium music app uses two layers:
- **Mini player bar** (compact, ~56-64px) -- always visible at bottom, shows: tiny album art (40x40), track title, single play/pause button, thin progress line. Tapping anywhere on the bar (not just play) expands to...
- **Full-screen now-playing view** -- album art dominates (or in our case, THE VISUALIZER), controls float below, swipe down to collapse back to mini bar.

**For viz-vibes:** Our visualizer IS the full-screen view. The mini bar should be the default resting state. Tapping the mini bar should "expand" by hiding the bar and letting the visualizer + floating controls take over the full viewport. Swipe down or tap a collapse chevron to return to mini bar + browse mode.

#### 2. Spotify Mobile Now-Playing Layout

- **Album art** takes ~60% of screen height (large, rounded corners, slight shadow)
- **Track title + artist** directly below art, left-aligned, title bold ~17px, artist lighter ~14px
- **Progress bar** full-width thin line (2px idle, 4px active), with elapsed/remaining times in small text
- **Controls row** centered: shuffle, prev, play/pause (largest, ~56px circle), next, repeat
- **Play/pause button** is 2-3x larger than other controls -- instant visual hierarchy
- **Background** uses extracted album art colors as a gradient wash behind everything
- **Mini bar at bottom** when browsing: 56px tall, album art thumbnail (40x40) on left, title truncated in middle, play/pause on right, hair-thin progress line at very top of the bar
- **Canvas feature**: 8-second vertical video loops replace static album art -- similar to what our visualizer does

**What to steal:**
- The mini bar layout: `[art] [title...] [play/pause]` with progress line at top edge
- Play/pause button being dramatically larger than skip buttons
- The expand/collapse animation between mini bar and full-screen
- Using our visualizer output as the "album art" background color source for the mini bar gradient

#### 3. Apple Music iOS 26 (Liquid Glass)

- **Full-screen animated album art** on lock screen -- artwork expands edge-to-edge and ANIMATES
- **Controls float** on top of artwork using translucent "Liquid Glass" material (frosted glass with depth)
- **No solid backgrounds** -- everything is semi-transparent layers over the artwork
- **Dynamic color extraction** from album art tints all UI elements
- **Track list** in albums/playlists: background color adapts to complement the artwork, not match it exactly
- **Motion and depth** everywhere -- controls feel like they hover over content

**What to steal:**
- Our glass-morphism approach is CORRECT and on-trend (Apple validated it in iOS 26)
- Controls should feel like they float over the visualizer, not sit in a separate bar
- Use `backdrop-filter: blur()` aggressively -- our existing glass-bg approach is right
- Consider extracting dominant color from visualizer frame to tint the player bar subtly
- The mini bar itself should have a glass/blur effect showing the visualizer through it

#### 4. TIDAL (March 2026 Redesign)

- **Album art is HUGE** -- square, no rounded corners, dominates the screen
- **Pure black background** makes artwork pop with extreme contrast
- **Dynamic background color** shifts to match current album
- **Minimal controls** below the art -- clean, uncluttered
- **Premium feel** comes from negative space and letting the art breathe

**What to steal:**
- Maximum space for the visualizer -- it should feel like the main event, not a decoration
- Dark/black negative space around controls increases perceived quality
- Fewer visible controls = more premium feel. Hide shuffle/repeat behind a menu or long-press

#### 5. YouTube Music Now-Playing (2025 Redesign)

- **Dual-pane layout**: now-playing top half, "Up Next" queue in bottom half with drag handle
- **Swipe left/right** on now-playing for prev/next track
- **Queue bottom sheet** with a drag handle -- pull up to see full queue, tap to expand
- **Swipe right on a track** to add to queue, **swipe left** to add to playlist
- **Action carousel** below controls (like, dislike, share, etc.) -- disappears when queue expands

**What to steal:**
- The "Up Next" preview below controls is clever -- shows 2-3 upcoming tracks without opening full drawer
- Swipe left/right for prev/next is natural and saves button space
- The drag handle on the queue sheet -- we already have this pattern planned with Vaul

#### 6. SoundCloud Waveform Player

- **Waveform IS the progress bar** -- much larger than a typical seekbar (~40px tall)
- **Fixed playhead** in center, waveform scrolls underneath it
- **Past audio** colored (orange), **future audio** gray -- instant visual feedback of position
- **Tap anywhere on waveform** to seek -- huge touch target
- **Waveform doubles as information** -- you can see loud vs. quiet sections

**What to steal:**
- Consider replacing our thin progress bar with a mini waveform visualization strip
- Even without a full waveform, making the progress bar THICKER on mobile (we already do 6px, but 8-10px with a color gradient would feel more intentional)
- The "colored past, gray future" pattern is universally understood

#### 7. Dark Glassmorphism Trend (2025-2026)

This is THE dominant aesthetic for premium dark-mode apps right now:
- **Ambient gradient orbs** -- vibrant blurs (purple, blue, pink) floating behind frosted glass panels
- **Frosted glass panels** with subtle white/colored borders (1px, ~10% opacity)
- **Glowing edges** on interactive elements -- neon-on-fog aesthetic
- **Deep dark backgrounds** (#0a0a0a, not pure black) with color coming from gradients
- Apple's Liquid Glass officially validated this direction at WWDC 2025

**What to steal:**
- We are ALREADY doing this with our glass-bg variables -- double down on it
- Add subtle glow/bloom to the play button on mobile (box-shadow with album/viz color)
- The mobile player bar border should have a faint glow, not just a solid line
- Consider a very subtle animated gradient in the player bar background that shifts with the visualizer

### Specific Actionable Recommendations for viz-vibes Mobile

#### A. Implement the Mini Bar -> Full Screen Pattern
```
MINI BAR (default when browsing):
+------------------------------------------+
| [progress line, 2px, full width]         |
| [vis-thumb 36x36] Title...  [>||] [^]   |
+------------------------------------------+
  56px tall, glass background, fixed bottom

FULL SCREEN (tap mini bar or chevron ^):
+------------------------------------------+
|                                          |
|          VISUALIZER FILLS ALL            |
|                                          |
|                                          |
|   (floating glass controls overlay)      |
|   Title - Artist                         |
|   [====progress bar========---] 2:31     |
|   [shuf] [<<] [ >|| ] [>>] [rep]        |
|                                          |
+------------------------------------------+
  Controls float over visualizer with glass bg
  Swipe down to collapse back to mini bar
```

#### B. Track List Drawer Improvements
- Show 2-3 "Up Next" tracks as a preview strip above the drawer handle (YouTube Music pattern)
- Add swipe-right-to-queue gesture on track items
- When drawer is at 40% snap point, show ONLY the search/filter bar + first ~5 tracks -- no scrolling needed for quick picks
- Track items: album art thumbnail (32x32) + title + duration on right, no other clutter

#### C. Player Controls Sizing (Mobile)
```
Play/pause button:  48px diameter (primary action, impossible to miss)
Skip prev/next:     28px icons with 44px touch targets (Apple minimum)
Shuffle/repeat:     20px icons, ONLY visible in full-screen mode, hidden in mini bar
Progress bar:       8px tall on mobile, 12px when being dragged
Seek thumb:         16px diameter, always visible on touch devices
```

#### D. Premium Feel Checklist
- [ ] Glass-blur player bar (not opaque) -- visualizer should bleed through subtly
- [ ] Play button with subtle glow matching dominant visualizer color
- [ ] Spring animation on expand/collapse (cubic-bezier(0.32, 0.72, 0, 1) -- iOS spring curve, already using this)
- [ ] Haptic feedback on play/pause if available (`navigator.vibrate(10)`)
- [ ] Track transitions: crossfade the title text, don't just swap it
- [ ] Progress bar: gradient from accent color to white, not solid color
- [ ] Mini bar: album art / viz thumbnail with 4px rounded corners, 1px glass border
- [ ] No visible scrollbars in track drawer -- use `scrollbar-width: none` on mobile
- [ ] Overscroll rubber-band effect in track drawer (CSS `overscroll-behavior: contain`)
- [ ] Loading states: skeleton shimmer on track items, pulsing play button while buffering

#### E. What NOT to Do (Anti-Patterns from Research)
- Do NOT show all controls at once on mobile -- it looks like a shrunk desktop site
- Do NOT use a hamburger menu for the track list -- bottom sheet/drawer is the standard for music apps
- Do NOT make the progress bar too thin to tap (minimum 44px touch target including padding)
- Do NOT auto-hide the mini bar -- it should always be visible when music is playing
- Do NOT use pure white text on glass -- use 90% opacity white for body, 100% only for titles
- Do NOT put the visualizer picker in a hamburger menu -- long-press the visualizer itself to cycle modes, or use a small floating pill
